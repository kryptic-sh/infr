# Phase 03 — LFM3 (`lfm3`)

**Why:** the most recent small family in the reference (added 2026-10-27), and
the one size its builder names is 1.7B, which both GPUs on the Windows box hold
resident. It also mixes short convolution layers with attention, which infr has
the pieces for.

## What the reference does

Read in `src/models/lfm3.cpp` (llama.cpp `5676dfbe0`): the hyper-parameter and
tensor loading (the first sixty lines), plus a listing of every key, tensor and
builder the file names. **Not read:** the graph body, and `lfm-base.cpp` (125
lines), which holds `build_lfm_base`, `build_lfm_shortconv` and
`build_lfm_dense_ffn`.

- **Two layer kinds.** A layer whose `n_head_kv` is 0 is a recurrent
  short-convolution layer (`shortconv.conv`, `shortconv.in_proj`,
  `shortconv.out_proj`, cache length from `shortconv.l_cache`); the others are
  attention layers.
- **Attention layers** always mix full and sliding-window layers: the pattern is
  read as an array (`attention.sliding_window_pattern`), the window from
  `attention.sliding_window`, and a separate RoPE base for the window layers
  (`rope.freq_base_swa`). They carry QK-norm (`attn_q_norm`, `attn_k_norm`) and
  an `attn_gate` tensor.
- **Optional sandwich norms:** `attn_post_norm` and `ffn_post_norm` are both
  present or both absent.
- A parallel FFN (`ffn_gate`, `ffn_up`, `ffn_down`); tied output embedding when
  `output.weight` is absent.
- **A non-causal mode:** when the file sets `causal_attn` false, full-attention
  layers read the prompt both ways while window layers stay causal
  (`LLAMA_NON_CAUSAL_TYPE_DENSE_ONLY`). Whether the shipped 1.7B file sets it is
  not known until the GGUF is dumped.
- The memory is a hybrid of a KV cache with sliding window and a recurrent state
  (`llama-memory-hybrid-iswa.h`).

## What infr already has

`Conv1dSilu` and the recurrent-state machinery built for `qwen35` (DeltaNet),
QK-norm, sandwich norms, dual-RoPE sliding-window attention for Gemma 3. Not
checked: whether the short convolution matches `Conv1dSilu` (kernel shape,
activation, where the cache sits), and what `attn_gate` gates.

## Steps

1. Pull the LFM3 GGUF and dump it; confirm the keys above and `causal_attn`.
2. Read `lfm-base.cpp` and the graph body of `lfm3.cpp` in full, and write the
   real delta here: the convolution's exact form, the gate, the layer order.
3. Decide from step 2 whether the short convolution composes from existing ops
   or needs one. If it needs one: CPU first, a parity case in
   `seam_op_parity.rs`, then Vulkan and Metal.
4. If the shipped file is non-causal on full-attention layers, that is a mask
   change in prefill and a decision about decode; settle it in this file before
   coding.
5. Recipe verification (CPU logits against `llama-cli`, CPU golden, GPU seam
   test, `infr run`), README row, CHANGELOG.

## Risks

- The recurrent state must survive the session paths that rewind or reuse a KV
  prefix (the `qwen35` state reset fixes of 2026-11 are the precedent).
- An oracle is only as good as the reference build; build llama.cpp on the
  Windows box first.
