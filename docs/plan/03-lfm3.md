# Phase 03 — LFM3 (`lfm3`)

**Why:** the most recent small family in the reference (added 2026-10-27), and
the one size its builder names is 1.7B, which both GPUs on the Windows box hold
resident. It also mixes short convolution layers with attention, which infr had
most of the pieces for.

**Status:** done on the CPU and Vulkan (2026-11-14). The Metal path is written
and compiled for the Apple target but has not run; the phase closes once CI's
macOS job has run its parity cases (`shortconv_parity`, `head_gate_parity` in
`crates/infr-metal/tests/parity.rs`). What it left is in `docs/backlog.md`
(B188, B189).

## The file

`LiquidAI/LFM3-1.7B-GGUF` (the publisher's repo, not gated),
`LFM3-1.7B-Q4_K_M.gguf`, 1099627808 bytes, and `LFM3-1.7B-F16.gguf`, 3466626336
bytes for the oracle, pulled with `infr pull` into the HF cache (snapshot
`cd0c74c5`). What the dump shows:

- `general.architecture = "lfm3"`, 24 blocks, 287 tensors, `n_embd` 2048,
  `feed_forward_length` 7680, 16 heads of 128 (`key_length` = `value_length` =
  `rope.dimension_count` = 128), `context_length` 262144.
- **Layer kinds:** `attention.head_count_kv` is a per-layer array, 0 on the 13
  short-convolution layers (0, 1 and every odd layer) and 4 on the 11 attention
  layers (2, 4, …, 22).
- **Window:** `attention.sliding_window_pattern` is a per-layer bool array, true
  on layers 4, 8, 12, 16 and 20, so 5 attention layers are sliding-window and 6
  (2, 6, 10, 14, 18, 22) are full. `attention.sliding_window` 256,
  `rope.freq_base` 1e6 on the full layers, `rope.freq_base_swa` 1e4 on the
  window layers.
- **`causal_attn`:** the file carries no `lfm3.attention.causal` key, so it is
  the causal model (llama.cpp's default is true).
- `rope_freqs.weight` (64 floats) is 1 for the first 32 pairs and 1e30 for the
  last 32: on the full layers half the NEOX pairs rotate and half stand still.
  The window layers take no divisors (`lfm3.cpp` creates the tensor for the
  non-window layers only).
- `shortconv.l_cache` 7; per short-convolution layer `shortconv.conv` [7, 2048]
  (f32), `shortconv.in_proj` [2048, 6144], `shortconv.out_proj` [2048, 2048].
- Per attention layer `attn_q`/`k`/`v`/`output`, `attn_q_norm`/`attn_k_norm`
  [128] and `attn_gate` [2048, 16]. Every layer has `post_attention_norm` and
  `post_ffw_norm` (the sandwich norms) and a SwiGLU FFN. No `output.weight`
  (tied to `token_embd`).
- Tokenizer `gpt2` with `pre = lfm2` (llama.cpp: the Llama-3 regex with
  `ignore_merges`, which infr already had), BOS `<|startoftext|>`, EOS
  `<|im_end|>`, `add_bos_token` false; the chat template is ChatML with
  `<think>`, and wraps assistant turns in `{% generation %}`.

## What the reference does

Read in full: `src/models/lfm3.cpp` and `lfm-base.cpp` (llama.cpp `5676dfbe0`).

- **Block:** `x += post_norm(mixer(norm(x)))`, then
  `x += post_ffw_norm(ffn(ffn_norm(x)))`; the post norms only when the file has
  them.
- **Short convolution** (`build_lfm_shortconv`): `in_proj` to `[B | C | X]`,
  `bx = B ⊙ X`, a causal depthwise conv over `bx` (`ggml_ssm_conv`, kernel width
  `l_cache`, the history holding the last `l_cache - 1` rows of `bx`, NO
  activation), `y = C ⊙ conv`, `out_proj`. The symmetric-padding branch for the
  non-causal model is unreachable for `lfm3` (its non-causal graph uses the
  memoryless overload, which pads causally).
- **Attention:** q/k/v projections, per-head RMSNorm on q and k, NEOX rope
  (`LLAMA_ROPE_TYPE_NEOX`) with each layer's base and the full layers'
  `rope_freqs`, attention scaled by 1/√128, then `attn ⊙ sigmoid(attn_gate · x)`
  with one gate per head, then `attn_output`.
- **Window:** `LLAMA_SWA_TYPE_STANDARD`, a key is masked when
  `query_pos - key_pos >= 256`, the window gemma3 already uses here.
- **Memory:** `llama_memory_hybrid_iswa` — a KV cache with a separate window
  cache for the attention layers, and a recurrent state of the convolution
  history per short-convolution layer, which rolls back only by snapshot.

## Design decisions

- **Two new ops, not compositions.** No existing op multiplies two slices of one
  buffer elementwise or convolves without SiLU, and `Op::GatedAct`'s sigmoid
  mode gates elementwise, not per head. Composing would have meant an identity
  activation on `GatedAct` and a no-SiLU flag on `Conv1dSilu` on all three
  backends anyway, plus two extra passes over `[rows, 3·n_embd]`.
  `Op::ShortConv` fuses `B ⊙ X`, the conv and `C ⊙` in one op with the
  `Conv1dSilu` state layout; `Op::HeadGate` broadcasts one sigmoid per head.
  - CPU: `causal_conv1d` (serial and parallel paths, bit-identical) serves both
    convs with a SiLU switch.
  - Vulkan: `-DSHORTCONV` builds of `conv1d_silu.comp`, `conv1d_silu_par.comp`
    and `conv1d_shift.comp` (input macro `CONV_IN`, output macro `CONV_OUT`; the
    default builds compute what they did), dispatched through the same recorder
    bodies (`ConvKind`); `head_gate.comp`.
  - Metal: `shortconv_f32` / `shortconv_par_f32` / `shortconv_shift_f32` beside
    the conv1d kernels, `head_gate_f32`, and a shared host fallback
    (`host_causal_conv`).
  - Both ops are replay-safe on Vulkan and Metal: no position, state mutated in
    a bound buffer, like `Conv1dSilu`.
- **Config:** `lfm3` gates its own parses: per-layer `shortconv_layers` (from
  `head_count_kv`, the attention layers' shared count becomes `n_kv`; differing
  counts are refused), `swa_layers` (which `is_swa_layer` answers from when
  non-empty), required `sliding_window`, `freq_base_swa` and `l_cache`,
  `rope_freq_factors`, and `sandwich_norm` (gemma, or an LFM3 file whose layers
  all carry both post norms; a layer with one is refused). A file with
  `attention.causal = false` is refused by name.
- **The recurrent state is generalised from qwen35, not copied.**
  `Config::is_recurrent_layer` / `recurrent_state_elems` / `has_recurrent_state`
  replace the `qwen35 && !is_qwen35_attn_layer` tests in the state allocation,
  graph declaration, fork, prefix seeding (a no-op), snapshot, the extend-only
  reuse rule and its zeroing, and the multi-GPU refusals. LFM3's history lives
  in the layer's K slot; its V slot is a one-element placeholder.
- **The SWA ring and the recurrent snapshot:** qwen35 has no window ring; LFM3
  does. Restoring the prefill-boundary snapshot resets `written_end`, which the
  ring rewind guard reads, so the resume arm now checks the ring (`ring_keeps`)
  against the high-water mark BEFORE restoring and falls back to a zeroed state
  otherwise. The extend arm cannot trip the guard (it reuses only a state whose
  `written_end` is `cached.len()`, and the ring holds `window + ubatch` rows),
  so that pairing is a `debug_assert`; a release build that ever got there
  zeroes the state and prefills from zero rather than panic.
- **KV estimates** price a recurrent layer at its fixed state size (they priced
  qwen35's as attention rows), so LFM3's 262144-token default context is not
  clamped by 13 layers of cache that do not exist. They price it twice: the live
  state and the one snapshot a slot holds (`SeamKv::mtp_delta_ckpt`, shared by
  qwen35's MTP rollback and the prefill-boundary snapshot, so never more than
  one copy). The old over-pricing had been the only room for that copy, whose
  allocation fails an MTP request outright.
- **Load-time refusals as in `lfm3.cpp`:** a file without
  `attention.layer_norm_rms_epsilon`, or with a full-attention layer and no
  `rope_freqs.weight`, is refused. A `shortconv.conv` (or qwen35 `ssm_conv1d`)
  stored as f16/bf16 is widened to f32 at load, since the Vulkan conv shaders
  read it as f32.

## Verified (Windows box, llama.cpp `5676dfbe0` CPU build)

- **Logits, CPU vs llama.cpp** (`cpu_prefill_matches_llama_debug_dump`, F16
  file, `llama-debug --save-logits` dumps):

  | prompt                                | tokens | max \|Δlogit\| | shared top-5 |
  | ------------------------------------- | -----: | -------------: | -----------: |
  | `The capital of France is`            |      5 |    0.003791809 |          5/5 |
  | `北京是中国的首都，它的历史`          |      9 |    0.003289938 |          5/5 |
  | lighthouse story ×2 + question (long) |   1092 |    0.002248764 |          5/5 |

  The long prompt is past the 256-token window and the 7-tap convolution, and
  spans two prefill chunks. Probability cosine at least 0.99999966 on all three.

- **Chat, multi-turn, in the model's own template:** `llama-debug` cannot parse
  special tokens, so the 61 chat ids came from llama-server's `/tokenize`
  (`parse_special`) and its `/completion` top-20 log-probabilities. Same top-5
  in the same order; top-1 over top-2 gap 0.48345 (infr) vs 0.48321 (llama.cpp).
  48 greedy tokens identical.
- **Greedy:** 40 tokens after the long prompt are identical to
  `llama-completion --temp 0 --repeat-penalty 1.0` (the GGUF asks for 1.1).
- **Vulkan vs llama.cpp** (`gpu_prefill_matches_llama_debug_dump`, Vulkan0, F16
  dumps): max |Δlogit| 0.03496313 (capital), 0.008563995 (long), 0.024199247
  (Chinese), 5/5 each.
- **Synthetic model vs llama.cpp, in CI:** llama.cpp `5676dfbe0` loads the
  four-layer synthetic LFM3 of `synthetic_lfm3.rs` (its vocabulary is 64
  single-character byte-level tokens, so a string of them tokenizes to known
  ids). Its last-position logits for a 24-token prompt are committed as
  `crates/infr-llama/tests/fixtures/synthetic_lfm3_llama_cpp.txt`;
  `synthetic_lfm3_cpu_matches_llama_cpp` holds infr's CPU to max |Δlogit| below
  1e-4 and measures 1.1086464e-5. Red with B and C swapped in the CPU short
  convolution (5.9914045), the head gate applied after `attn_output`
  (3.2253044), the head gate dropped (2.7693543) and the window pattern ignored
  (1.9120011).
- **The F16 oracle holds a bound:** `cpu_prefill_matches_llama_debug_dump_lfm3`
  (model- and dump-gated) asserts max |Δlogit| below 0.02 on a dump past the
  window: 0.002248764 on the 1092-token prompt; red with the head gate dropped
  (5.4831944) and the window pattern ignored (5.19669).
- **Template:** infr's render of a system + user + assistant + user conversation
  equals llama-server's `/apply-template` output byte for byte, with thinking on
  and off (`lfm3_render_matches_the_reference`, `infr-chat`).

### Performance against llama.cpp

pp512 / tg128 with `infr bench` and `llama-bench`, three reps, CPU 1–3% busy
before each run, no quiet window arranged: in t/s, Vulkan0 7259.0 / 488.6 (infr)
against 10103.09 / 379.54; Vulkan1 138.3 / 23.6 against 195.94 / 25.11; CPU
565.5 / 51.3 against 1082.25 / 60.43. Prefill trails everywhere; decode leads on
the 7900 XTX and trails on the integrated GPU and CPU. Not profiled — B188.

The generic llama.cpp oracle test (`cpu_prefill_matches_llama_debug_dump`) stays
green with the head gate dropped (max |Δlogit| 5.780733, 3/5) and with the
window pattern ignored (5.19669 on the long prompt, 4/5) at its model-agnostic
floors; the LFM3 sibling above is the check. A text-level no-rewind session test
passed with the zeroing removed (the convolution reaches six tokens back, so
stale history did not move an 8-token answer) and was not added (B189).
